01 / OFFLINE FIELD SYSTEMS

When the network disappears, the work shouldn't.

Field work doesn't stop because the signal does. The job carries on in places where coverage is patchy, intermittent, or just absent.

  • OFFLINE-FIRST
  • SWIFTDATA
  • SYNC ENGINE
  • CONFLICT RESOLUTION
  • PAGINATION
  • IDEMPOTENCY

The problem

The reflex is to treat offline as an error. Show a spinner, block the screen, tell people to try again later. That turns a coverage problem into a work stoppage, and it puts the network between someone and their job.

How it behaves when coverage drops

  1. 01

    ONLINE

    The device has a connection. Queued changes drain in the background and nobody has to think about it.

  2. 02

    CONNECTION LOST

    Coverage goes mid-task. No dialog, no blocked screen, no spinner sitting between someone and their job.

  3. 03

    WORK CONTINUES

    Reads and writes land in the local store and return immediately. As far as the interface is concerned, nothing changed.

  4. 04

    QUEUED

    Every change is appended to a durable queue, each with its own key, so the same edit can never be applied twice.

  5. 05

    SYNC

    Coverage returns. The queue replays in order and the server discards anything it has already seen.

  6. 06

    CONSISTENT STATE

    Both sides converge. Conflicts resolve by a documented rule rather than by asking someone to choose.

The approach

So the local store becomes the source of truth. Reads and writes land locally and return straight away. Syncing happens in the background and reconciles later, rather than sitting in front of the user as a gate.

That pushes the difficulty where it belongs: reconciliation. Records edited in two places have to converge predictably. Ordering has to survive a queue replayed six hours later. A retry can never double-apply work that already landed.

We stopped asking how to cache data, and started asking how to make the network irrelevant to the workflow.

The part that took the longest

Reconciliation. Two people editing the same record in different places have to converge to the same answer, and that answer has to be defensible without a human adjudicating it.

What the work involved

  • The constraint

    Connectivity can't be a prerequisite for doing the job.

  • The engineering

    Local persistence, a sync engine, retry and conflict handling built around the workflow.

  • The ownership

    Architecture, iOS implementation, performance and platform standards.

  • The outcome

    A workflow designed around reality instead of a perfect network.
