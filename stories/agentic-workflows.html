04 / AGENTIC WORKFLOWS

An assistant is useful when it can do something.

Most assistants answer questions. The ones worth building finish the task, which means the model is one component inside a system rather than the system itself.

  • AI AGENTS
  • LLM
  • TOOL CALLING
  • STRUCTURED OUTPUT

The problem

Once a model can trigger real actions, the engineering problem stops being about prompts. It becomes a question of boundaries. Which tools exist, what each one is allowed to touch, what gets checked before anything commits, and what happens when the model is confidently wrong.

How a request becomes an action

  1. 01

    INTENT

    Natural language. Ambiguous, often incomplete, and occasionally asking for something that is not permitted.

  2. 02

    AGENT

    Matches the intent against a fixed set of tools. It proposes a course of action; it does not get to decide.

  3. 03

    TOOL CALL

    Emitted as a typed, schema-checked structure. Anything malformed or out of range stops here and never reaches the system.

  4. 04

    POLICY

    Permissions and business rules run in ordinary code, on the same path a request from a person would take.

  5. 05

    ACTION

    Only now does anything execute against the real system.

  6. 06

    RESULT

    Confirmed back, with an audit entry indistinguishable from one a human started.

The approach

So the model proposes and the code decides. Intent gets parsed into a structured call against a fixed set of tools. Business rules validate that call in ordinary code, the same rules guarding every other path into the system. Only then does anything run.

That boundary is what makes the feature shippable. It keeps the worst case at "I couldn't do that" instead of an action nobody authorised, and the audit trail comes out identical whether a person or an agent started the work.

The chat is the easy half. Everything that has to be true before an action runs, that's the work.

The part that took the longest

The validation layer. Making the failure mode a refusal rather than a wrong action is what decides whether the feature can ship at all.

What the work involved

  • The constraint

    A model that will sometimes be confidently wrong.

  • The engineering

    A fixed tool surface, schema-checked calls, and policy validation in ordinary code.

  • The ownership

    Agent architecture, the safety boundary and the audit trail.

  • The outcome

    Actions that are either authorised and logged, or refused outright.
